# تقييم أثر حماية البيانات (DPIA) — مسودة للاعتماد

| | |
|---|---|
| **النظام** | Iqama Screener — فحص أهلية حاملي الإقامات/الهويات لإصدار تصاريح العمل |
| **المتحكّم (Controller)** | الشركة الطالبة للتصريح *(يُعبَّأ)* |
| **المعالج (Processor)** | مشغّل النظام إن اختلف *(يُعبَّأ)* |
| **المرجع النظامي** | نظام حماية البيانات الشخصية (PDPL) ولائحته التنفيذية — سدايا |
| **الحالة** | مسودة — تحتاج اعتماد مسؤول الخصوصية ومالك البيانات قبل أي بيانات حقيقية |
| **التاريخ** | 2026-10-07 |

## 1. وصف المعالجة
| البند | الوصف |
|---|---|
| الغرض | التحقق من أهلية العامل (سريان الإقامة، نوع الكفيل، المهنة، الجنسية) قبل إصدار تصريح دخول/عمل لمشروع محدد |
| الأساس النظامي | تنفيذ عقد/التزام تعاقدي بين الشركة الطالبة وجهة إصدار التصريح (المادة 6 PDPL — يُثبَّت بالإحالة للعقد *(رقم العقد يُعبَّأ)*) |
| أصحاب البيانات | العمال المقيمون والمواطنون المرشحون للعمل في المشروع |
| فئات البيانات | صورة بطاقة الهوية/الإقامة، الاسم (عربي/إنجليزي)، رقم الهوية، تاريخ الميلاد، الجنسية، المهنة، صاحب العمل، تاريخ الانتهاء؛ **الديانة** تُقرأ من البطاقة وتُخزَّن كحقل غير حرج — يُوصى بإسقاطها (انظر 5) |
| المصدر | صور يقدّمها العامل أو صاحب العمل |
| المستلمون | مراجعو الشركة الطالبة؛ جهة إصدار التصريح (تستلم طلب التصريح المطبوع) |
| النقل خارج المملكة | **لا يوجد.** المعالجة محلية على خادم داخل المملكة *(يُؤكَّد موقع الخادم عند اختيار المزوّد)*؛ لا OCR سحابي ولا نماذج لغوية خارجية (`ocr.external.enabled: false`) |
| مدة الاحتفاظ | صور البطاقات: حتى إصدار طلب التصريح ثم تُحذف. السجلات: 365 يوماً (`data_retention_days`) *(يُعتمد)* |
| القرار الآلي | لا قرار نهائي آلي بالقبول؛ الرفض الآلي محصور في حالات قاطعة (انتهاء، كفالة فردية، مهنة مستثناة) ويمكن مراجعته بشرياً |

## 2. الضرورة والتناسب
- الحقول المستخرجة محصورة فيما تحتاجه القواعد؛ صورة الوجه لا تُخزَّن منفصلة.
- البديل اليدوي (قراءة بشرية لكل بطاقة) يعرّض نفس البيانات لعدد أكبر من الأشخاص وبلا سجل تدقيق.
- **إجراء مطلوب:** إيقاف استخراج حقل الديانة ومكان الميلاد إذ لا تدخلان في أي قاعدة (تقليل البيانات).

## 3. المخاطر على أصحاب البيانات
| # | الخطر | الاحتمال | الأثر | التخفيف الحالي | المتبقي |
|---|---|---|---|---|---|
| 1 | وصول غير مصرح للبيانات | متوسط | عالٍ | تشفير AES-256، HTTPS، كلمة مرور، مفتاح API إلزامي، إخفاء الأرقام | **متوسط** — حتى تطبيق هويات فردية + MFA (المرحلة 1) |
| 2 | قرار خاطئ يحرم العامل من التصريح | منخفض | عالٍ | عتبات ثقة، مراجعة بشرية، أسباب مفسَّرة، إمكانية التصحيح | منخفض |
| 3 | تسرّب ملف التصريح بعد التصدير | متوسط | عالٍ | ZIP مشفّر بكلمة مرور تُرسل عبر قناة أخرى؛ تسجيل المستلم | منخفض–متوسط |
| 4 | احتفاظ أطول من اللازم | منخفض | متوسط | حذف الصور بعد التصدير؛ تطهير مجدول | منخفض |
| 5 | فقدان البيانات | متوسط | متوسط | نسخ احتياطي مشفّر ليلي خارج الخادم + مفتاح escrow | منخفض |
| 6 | تمييز بسبب تخطيط بطاقة أقدم | منخفض | متوسط | توجيه للمراجعة مع ملاحظة طلب نسخة أبشر | منخفض |

## 4. حقوق أصحاب البيانات
| الحق | الآلية |
|---|---|
| العلم | إشعار الخصوصية في صفحة الرفع + يُقدَّم للعامل عند جمع الصورة *(نموذج ورقي/رسالة يُعبَّأ)* |
| الاطلاع | طلب لمالك البيانات → تصدير سجل المستند من الـ API |
| التصحيح | شاشة المراجعة (القيمة الأصلية تُحفظ) |
| الحذف | `DELETE /documents/{id}` يحذف البيانات والصورة ويسجّل الحدث |
| الاعتراض على القرار | إعادة الفحص بشرياً عبر المراجع |
**مدة الرد:** *(يُعتمد — يُوصى بـ 30 يوماً كحد أقصى)*.

## 5. الإجراءات المطلوبة قبل الاعتماد
- [ ] تعبئة أسماء المتحكّم/المعالج ورقم العقد والأساس النظامي
- [ ] تأكيد موقع الخادم داخل المملكة
- [ ] اعتماد جدول الاحتفاظ (365 يوماً أو غيره)
- [ ] إسقاط حقلي الديانة ومكان الميلاد من الاستخراج
- [ ] توقيع اتفاقية معالج مع الشركة الطالبة (المرحلة 1)
- [ ] تعيين مسؤول خصوصية وإدراج النظام في سجل أنشطة المعالجة (المرحلة 1)
- [ ] اعتماد إجراء بلاغ الخرق خلال 72 ساعة لسدايا (المرحلة 1)
